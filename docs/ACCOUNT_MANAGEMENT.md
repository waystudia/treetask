# Управление аккаунтами TreeTask

## Модель безопасности

- Браузер использует только publishable key.
- Создание аккаунтов, сброс временного пароля и удаление Auth-пользователя
  выполняет защищённая Edge Function `account-management`.
- Текущий пароль невозможно прочитать ни пользователю, ни суперадминистратору.
  При восстановлении создаётся новый временный пароль, который показывается один
  раз и должен быть заменён после входа.
- Суперадминистраторы хранятся в `public.platform_admins`. Для таблицы включён
  RLS и нет клиентских разрешений. Проверка выполняется через узкую функцию
  `is_platform_admin()` без выдачи табличных прав.

## Первичное назначение суперадминистратора

После регистрации владельца выполните один раз в Supabase SQL Editor, подставив
email владельца:

```sql
insert into public.platform_admins (user_id, created_by)
select id, id
from auth.users
where lower(email) = lower('owner@example.com')
on conflict (user_id) do nothing;
```

Назначение нельзя делать автоматически «первому пришедшему» пользователю: при
открытой регистрации это позволило бы постороннему захватить административные
права.

## Удаление данных

Пользователь может отдельно:

1. очистить только IndexedDB текущего устройства;
2. удалить свои проекты и данные, сохранив Auth-аккаунт;
3. удалить аккаунт полностью.

Перед удалением Edge Function удаляет файлы через Storage API, затем вызывает
привязанную к текущему `auth.uid()` транзакционную функцию `purge_my_data()` и,
при полном удалении, удаляет Auth-пользователя. Функция не принимает чужой
идентификатор, поэтому пользователь может очистить только собственные данные.
Связанные refresh-токены после этого больше нельзя использовать.
